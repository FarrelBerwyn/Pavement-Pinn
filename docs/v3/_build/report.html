0.2 Delapan hal terpenting

Satu kalimat proyek (v3.1): PAVEMENT-PINN mengubah foto lubang dari warga menjadi daftar perbaikan berbasis risiko yang dapat diaudit: AI di perangkat Intel memverifikasi dan mengukur kerusakan, mesin fisika perkerasan yang dapat diverifikasi menilai seberapa cepat struktur gagal pada kondisi basah dan beban truk, lalu petugas memutuskan dengan bukti, bahkan tanpa internet di lapangan.

  1. Perangkat dulu. Pastikan laptop Intel Core Ultra dengan NPU (yang akan dipakai saat wawancara) dan lingkungan Python 3.11/3.12 tersedia. Tanpa keduanya, M2–M5 tidak bisa dimulai dan Metric 03 tetap mendekati nol (D-21, D-23).
  2. Selesaikan Fase 0 hari ini. Sebagian sudah dikerjakan di working tree (file OpenVINO/WIM simulasi dihapus, no-fake-claims.test.ts ditambahkan, tidak ada Math.random di src/ dan server/). Sisa: koridor Narogong, DECISION_LOG.md, sitasi + SDG + biaya di repo, lembar pengungkapan GenAI, commit yang rapi.
  3. Fisika yang benar sebelum AI. PyMastic (Apache-2.0, dibandingkan dengan KENPAVE dan WESLEA oleh pembuatnya [18]) menjadi acuan. Tes acuan εt ≈ 303 µε dan εv ≈ 793 µε adalah CONTOH DOKUMEN sampai dijalankan ulang di repo tim.
  4. "PINN" didefinisikan jujur sebagai physics-informed neural surrogate (D-02): dilatih dari solusi PyMastic, fisika masuk lewat variabel tanpa dimensi dan loss monotonisitas, dengan pengaman kembali ke solver di luar domain.
  5. AI nyata yang terlihat juri: deteksi YOLO yang diekspor ke OpenVINO INT8, Monte Carlo P10/P50/P90 lewat surrogate OpenVINO, dan ringkasan SLM lokal di NPU dengan pemeriksa angka.
  6. Halaman Bukti hanya membaca measurements/*.json dari laptop wawancara. Selama file belum ada, UI menulis "belum diukur" (D-11).
  7. Bawa audit Anda sendiri. Slide "Apa yang kami temukan dan perbaiki" mengubah temuan P0 menjadi bukti Responsible AI.
  8. Jangan mendemokan yang belum lulus gerbang. Fitur yang belum lulus disebut TARGET/RENCANA; siapkan rekaman cadangan.

3.1 Nilai unik dalam satu paragraf

4 Spesifikasi Teknis AI dan Fisika (untuk Developer)

Bagian ini adalah kontrak kerja developer. Setiap modul memuat tujuan, algoritma, data, metrik, kriteria lulus, apa yang boleh diklaim, dan status hari ini. Kode referensi ada di Lampiran B (docs/v3/_build/reference_code/, salin ke inference/core/).

Status kode referensi (dibaca jujur)

Paket referensi menandai pavement_core.py, test_core.py, trust_gate.py, gen_mlet_dataset.py, mc_life.py sebagai DIUJI di lingkungan penyusun v3.0, dan train_pi_surrogate.py, train_yolo.py, slm_brief.py, bench_tools.py sebagai BELUM DIUJI. Audit 16 Okt tidak dapat menjalankan satu pun karena Python belum terpasang di mesin yang diaudit. Bagi tim, semua berstatus BELUM DIUJI sampai python test_core.py mencetak ALL TESTS PASSED di repo tim (gerbang M1).

Prinsip desain yang tidak boleh dilanggar

  1. Fisika adalah acuan, AI adalah percepatan dan persepsi. Setiap angka struktural dapat dihitung ulang dengan PyMastic.
  2. Tidak ada angka tanpa asal-usul. Setiap keluaran menyimpan versi model, perangkat, input dan satuan, serta label MEASURED | COMPUTED | DEFAULT | ASSUMED.
  3. Gagal dengan jujur. Model tidak yakin atau input di luar rentang → sistem mengatakannya dan meminta manusia.
  4. Deterministik. Input sama → output sama, termasuk Monte Carlo (seed = hash id segmen + versi) (F-21).
  5. Tidak ada laporan yang dibuang diam-diam.

4.4 Modul D: Mesin struktural (MLET + PI-surrogate + Indeks Umur)

D1. Acuan fisika: teori elastis berlapis (MLET) dengan PyMastic

Asumsi: lapisan linear-elastis, isotropik, homogen, antarmuka terikat penuh, beban lingkaran seragam tekanan q (default 0,55 MPa), tanah dasar setengah ruang. Keluaran: εt di dasar lapis aspal (retak lelah) dan εv di puncak tanah dasar (alur struktural). PyMastic berlisensi Apache-2.0 dan README-nya membandingkan hasil dengan KENPAVE dan WESLEA [18]. Catatan risiko: repositori PyMastic terakhir diperbarui 2020; kunci versinya dengan hash commit dan uji tiap pembaruan.

Verifikasi silang dari v3.0 CONTOH DOKUMEN

Segmen default (AC 100 mm/2500 MPa; base 150 mm/200 MPa; CBR 6 → 60 MPa; ν 0,35/0,35/0,45; 4 ban terisolasi 0,55 MPa): εt = 303 µε, εv = 793 µε pada sumbu 10 t; 274/663 µε pada 8,16 t; sama dengan solver independen audit. Uji kesebangunan: semua modulus × 3 → regangan ÷ 3. Mesin lama memberi 20/17 µε. Tim wajib menjalankan ulang (test_core.py) sebelum menyebutnya — gerbang M1.

  • PyMastic mengalikan E dengan 1000: bila E dalam MPa, berikan q dalam kPa (0,55 MPa → 550).
  • Konvensi tanda: tekan positif → εt = −Strain_R.
  • Normalisasi panjang dengan jari-jari kontak a; pakai iteration=20 (40 menghasilkan NaN pada ±45% struktur tebal di uji v3.0). Selalu periksa NaN dan tolak.
  • Roda ganda: hitung di x = 0, d/2, d (d default 330 mm, dapat disunting), superposisikan, ambil maksimum.

D2. PI-surrogate: jaringan saraf berbasis fisika

Mengapa perlu? Keputusan jujur butuh ketidakpastian: Monte Carlo 2.000 sampel × 3 kondisi × 4 opsi × 200 segmen = 4,8 juta evaluasi. Dengan MLET (±13 ms/kasus pada uji v3.0 CONTOH DOKUMEN) ±17 jam CPU; surrogate memungkinkan ini interaktif di laptop. Waktu nyata wajib diukur ulang di perangkat tim (M5).

  1. Analisis dimensi (pasti): x = [ln(h1/a), ln(h2/a), ln(E1/E3), ln(E2/E3)], y = [ln(εt·E3/q), ln(εv·E3/q)] → kesebangunan elastis dan kelinearan terhadap q terpenuhi apa pun bobotnya; regangan selalu positif.
  2. Loss monotonisitas pada titik kolokasi (autograd): L = MSE + λ_m·mean(ReLU(−s_jk·∂y_k/∂x_j)²), λ_m ≈ 0,1. Aktifkan hanya arah yang konsisten 100% pada data PyMastic (pemeriksaan B.9). Kandidat: εv turun bila h1, h2, E1/E3, E2/E3 naik; εt turun bila E2/E3 naik. Jangan paksa εt terhadap h1.
  3. Pengaman: di luar kotak domain latih atau uji silang acak 1-dari-50 berselisih > 10% → pakai PyMastic dan tandai.

Data latih: 5.000–20.000 solusi PyMastic, Latin hypercube: sumbu 6–25 t, q 0,5–0,8 MPa, h1 50–250 mm, h2 100–400 mm, E1 1.000–5.000 MPa, E2 100–500 MPa, CBR 2–15 (E3 = k·CBR, k default 10 berlabel ASSUMED).

Validasi wajib: (1) uji acak 20%: R², MAPE, galat p95; (2) uji di luar distribusi (latih CBR ≥ 4 dan h1 ≤ 180 mm; uji CBR < 3 atau h1 > 200 mm); (3) kesebangunan; (4) % titik kolokasi melanggar arah; (5) ablasi MLP biasa vs PI-surrogate. Simpan models/pi_surrogate_metrics.json.

5.3 Alasan memilih teknologi Intel (M03 1.2, 4 poin)

  1. Satu runtime untuk CPU, iGPU, NPU. Laptop dinas dan kampus umumnya tanpa GPU diskrit. OpenVINO menjalankan model yang sama di ketiga unit (AUTO), sehingga satu basis kode melayani laptop biasa (mode CPU-saja) maupun AI PC.
  2. Kuantisasi dengan kontrol akurasi (NNCF). Galat regangan diperbesar oleh fungsi transfer berpangkat 3–7; deviasi tiap presisi harus diukur. Bila INT8 merusak akurasi surrogate, tetap di FP16 dan laporkan.
  3. GenAI lokal di NPU (OpenVINO GenAI). Data infrastruktur dan lokasi tidak keluar perangkat; berfungsi tanpa internet; hemat daya.
  4. Ekosistem siklus penuh. sklearnex untuk analisis, PyTorch XPU untuk pelatihan di GPU Intel, Optimum Intel untuk ekspor SLM, benchmark_app untuk bukti.
  5. Perbandingan yang adil. TensorRT butuh GPU NVIDIA; ONNX Runtime dapat memakai OpenVINO sebagai execution provider. Klaim "lebih cepat" hanya dari benchmark sendiri (PyTorch CPU vs OpenVINO FP32/FP16/INT8 pada perangkat yang sama).

Agar dapat nilai penuh, setiap alasan harus dipasangkan dengan angka terukur di Halaman Bukti (mis. alasan 1 ↔ latensi mode CPU-saja vs AUTO; alasan 2 ↔ tabel deviasi INT8; alasan 3 ↔ token/detik NPU + demo Wi-Fi mati).

12.2 AI, fisika, dan model

Q8. Is it really a PINN? (B)
It is a physics-informed neural surrogate, not a PINN that solves the PDE from collocation residuals. Physics enters in two ways: dimensionless inputs and outputs make elastic similarity and load scaling hold exactly, and an autograd penalty enforces physically required monotonic trends at unlabelled collocation points. The reference is a layered-elastic solver, and we fall back to it outside the training domain.

"""pavement_core.py - reference logic for PAVEMENT-PINN v3 (Modules D, E, F, G-checker).
Units: lengths mm, moduli MPa, pressure MPa, loads tonnes (converted to kN), strain in microstrain.
"""
import math, re, sys
import numpy as np

# ---------- Module D1: MLET reference via PyMastic (Apache-2.0) ----------
def mlet_strains(axle_t, h_mm, E_mpa, nu, q_mpa=0.55, tyres_per_axle=4,
                 dual_spacing_mm=None, pymastic_path=None, iteration=20):
    """Critical strains (microstrain) for a single axle.
    h_mm: thicknesses of bound/unbound layers above subgrade, e.g. [100, 150]
    E_mpa, nu: one value per layer incl. subgrade, e.g. [2500, 200, 60]
    Returns dict(et, ev, a_mm). et = horizontal tensile at bottom of layer 1 (asphalt),
    ev = vertical compressive at top of subgrade. Positive values.
    """
    if pymastic_path:
        sys.path.insert(0, pymastic_path)
    from Main.MLE import PyMastic  # PyMastic sign convention: compression positive
    assert len(E_mpa) == len(nu) == len(h_mm) + 1, "E and nu need one entry per layer incl. subgrade"
    if axle_t <= 0 or min(h_mm) <= 0 or min(E_mpa) <= 0:
        raise ValueError("load, thickness and moduli must be positive")
    wheel_N = axle_t * 9.80665e3 / tyres_per_axle
    a = math.sqrt(wheel_N / (math.pi * q_mpa))          # contact radius, mm
    s = a                                               # normalise lengths by a (numerical stability)
    z_t = (h_mm[0] - 0.01) / s                          # just above bottom of asphalt

    # PyMastic multiplies E by 1000 internally -> pass q in kPa when E is in MPa

    er, ez = RS['Strain_R'], RS['Strain_Z']

def allowable_reps(et_ue, ev_ue, E1_mpa, criterion="AI"):
    """Allowable standard-axle repetitions to fatigue (Nf) and subgrade rutting (Nd).
    AI  = Asphalt Institute (1982), as given in Huang, Pavement Analysis and Design: E in psi, strain in in/in.
    AUS = Austroads (2004) subgrade criterion form N = (9300/ue)^7; asphalt fatigue needs Vb and mix modulus,
          so it is passed separately. VERIFY constants against the Austroads/MDP 2017 edition you cite.
    """
    if criterion == "AI":
        E_psi = E1_mpa * 145.0377
        Nf = 0.0796 * (et_ue * 1e-6) ** -3.291 * E_psi ** -0.854
        Nd = 1.365e-9 * (ev_ue * 1e-6) ** -4.477
    elif criterion == "AUS":
        Vb = 11.0  # % binder volume, editable
        Nf = (6918 * (0.856 * Vb + 1.08) / (E1_mpa ** 0.36 * et_ue)) ** 5
        Nd = (9300.0 / ev_ue) ** 7
    else:
        raise ValueError(criterion)
    return Nf, Nd

def life_index_years(Nf, Nd, esal_per_year, growth=0.04, damage_used=0.0):
    """Years until cumulative ESAL consumes the remaining allowable repetitions (Miner's rule),
    with geometric traffic growth. Indicative only."""
    N = min(Nf, Nd) * max(0.0, 1.0 - damage_used)
    if esal_per_year <= 0:
        return float("inf")
    if growth == 0:
        return N / esal_per_year
    return math.log(1 + N * growth / esal_per_year) / math.log(1 + growth)

def priority_score(cls, sev, aadt_norm, moto_share, unlit, life_p50_years, n_confirm,

    Q = 1.0 if underreported else 0.0

    return round(100 * sum(parts.values()), 1), {k: round(100 * v, 1) for k, v in parts.items()}

def knapsack(items, budget, unit=1_000_000):
    """items: list of (id, cost_rp, benefit). Exact 0/1 DP on costs rounded up to `unit`."""
    W = int(budget // unit)
    costs = [max(1, math.ceil(c / unit)) for _, c, _ in items]
    best = np.zeros(W + 1); keep = np.zeros((len(items), W + 1), dtype=bool)
    for i, (_, _, b) in enumerate(items):
        c = costs[i]
        if c > W:
            continue
        cand = best[:W + 1 - c] + b
        better = cand > best[c:]
        keep[i, c:] = better
        best[c:] = np.where(better, cand, best[c:])
    chosen, w_ = [], W
    for i in range(len(items) - 1, -1, -1):
        if keep[i, w_]:
            chosen.append(items[i][0]); w_ -= costs[i]
    return chosen[::-1], float(best[W])

def greedy(items, budget):
    chosen, spent, total = [], 0, 0.0
    for id_, c, b in sorted(items, key=lambda t: t[2] / t[1], reverse=True):
        if spent + c <= budget:
            chosen.append(id_); spent += c; total += b
    return chosen, total

        colloc = lo + (hi - lo) * torch.rand(1024, 4, device=dev)          # unlabelled physics points

"""bench_tools.py - reproducible OpenVINO benchmark -> measurements/*.json (single source for the Evidence page).
NOT executed during document prep. Protocol: 50 warm-up, >=1000 timed runs, p50/p95/p99, cold start, deviation vs FP32.
"""
import json, time, platform, hashlib, datetime, sys
import numpy as np

def bench(xml, device, inputs, ref_xml=None, warmup=50, runs=1000, out=None):
    import openvino as ov
    core = ov.Core()
    t0 = time.perf_counter(); cm = core.compile_model(xml, device); cold = (time.perf_counter() - t0) * 1000
    req = cm.create_infer_request()
    for _ in range(warmup): req.infer(inputs)
    ts = []
    for _ in range(runs):
        t = time.perf_counter(); req.infer(inputs); ts.append((time.perf_counter() - t) * 1000)
    res = dict(model=xml, sha256=hashlib.sha256(open(xml.replace(".xml", ".bin"), "rb").read()).hexdigest()[:16],
               device=device, device_name=core.get_property(device, "FULL_DEVICE_NAME"),
               available_devices=core.available_devices, openvino=ov.get_version(),
               batch=int(np.asarray(list(inputs.values())[0] if isinstance(inputs, dict) else inputs).shape[0]),
               cold_start_ms=cold, p50_ms=float(np.percentile(ts, 50)), p95_ms=float(np.percentile(ts, 95)),
               p99_ms=float(np.percentile(ts, 99)), runs=runs, host=platform.platform(),
               date=datetime.datetime.now().isoformat(timespec="seconds"), power="not measured")
    if ref_xml:   # numerical deviation vs FP32 reference on the same inputs
        ref = core.compile_model(ref_xml, "CPU")(inputs)[0]; got = cm(inputs)[0]
        res["max_abs_dev_vs_fp32"] = float(np.max(np.abs(got - ref)))
        res["max_rel_dev_vs_fp32"] = float(np.max(np.abs(got - ref) / (np.abs(ref) + 1e-9)))
    if out: json.dump(res, open(out, "w"), indent=2)
    return res
